# 1.3. Package 2 — Charging Infrastructure Co-optimisation

Package 2 solves a mixed-integer cost-minimisation problem that jointly determines the optimal charging infrastructure and fleet charging strategy. It requires a schedule generated by Package 1 and the Gurobi solver.

**Notebook:** `notebooks/2_Co-optimisation.ipynb`

## What the Package does

Given the fleet schedules from Package 1, the co-optimisation model decides:

- **How many chargers** of each type to install at the depot (f1, f2, f3, f4) and on route
- **When and how much** each vehicle charges at each timestep
- **Energy procurement** from the grid at depot vs. on route

The objective is to minimise total annualised cost, which includes annualised infrastructure investment (charger purchase + installation + maintenance), depot electricity cost (grid price + fixed rate), route charging cost, demand charges (peak power), and subscription fees.

## Charger types

The model considers five charger categories:

| Type | Description | Typical power |
|------|-------------|---------------|
| f1 | Slow depot charger | 7.4 kW |
| f2 | Medium depot charger | 50 kW |
| f3 | Fast depot charger | 150 kW |
| f4 | Ultra-fast depot charger | 350 kW |
| route | Route charger (used while away from depot) | 150 kW |

Power levels, investment costs, installation costs, and maintenance costs are all configurable through `infrastructure_configuration.yaml` or custom overrides.

## Step-by-step walkthrough

### 1. Ensure Package 1 has run

The optimisation reads the schedule CSV produced by Package 1. Make sure `data/Output/schedule_<N>/schedule_<N>.csv` exists.

### 2. Edit the configuration

**`config/run_Optimisation_Config.yaml`** defines:

- `schedule_name` and `schedule_number` — which schedule to optimise
- `electricity_price_file` — filename of the price CSV in `data/Input/`
- `EVs` — number of vehicles (must match the schedule)
- `MIPGap` — solver optimality gap (e.g. 0.005 = 0.5%)
- `infrastructure_configurations` — set to `predefined` to use the standard infrastructure parameters, or `custom` to use parameters defined in this same file

### 3. Open the notebook

```bash
jupyter lab
# Open notebooks/2_Co-optimisation.ipynb
```

### 4. Run the cells

The notebook follows this structure:

1. **Import dependencies** — loads libraries, config loaders, and optimisation functions.
2. **Load configuration** — reads the YAML files and displays cost and power parameters for review.
3. **Data validation** — prints the shape and head of each input DataFrame to verify correctness.
4. **Run optimisation** — calls `optimisation()`, which builds and solves the Pyomo model with Gurobi.
5. **Save results** — exports result CSVs to `data/Output/<schedule_name>/Results/`.
6. **Visualisation** — generates summary graphs.

### 5. Review outputs

Results are saved to `data/Output/<schedule_name>/Results/`:

| File | Content |
|------|---------|
| `<N>_Main_variables_results.csv` | Hourly aggregated charging energy, grid purchases, costs, and charger usage |
| `<N>_results_summary.csv` | Cost summary by charger type and category |
| `<N>_results_per_EV.csv` | Per-vehicle, per-hour detailed results |
| `<N>_max_variable_per_hour.csv` | Maximum values by hour (post-processing) |
| `<N>_avg_variable_per_hour.csv` | Average values by hour (post-processing) |

## Optimisation model overview

The model is formulated as a mixed-integer linear programme (MILP):

- **Decision variables:** number of chargers per type (integer), charging energy per vehicle per timestep (continuous), grid purchases (continuous), storage levels (continuous)
- **Constraints:** battery capacity limits (SoC between 20-80% by default), charging station capacity, energy balance, vehicle availability (depot charging only when at depot)
- **Objective:** minimise total annualised cost

Infrastructure costs are annualised using a capital recovery factor based on the discount rate and equipment lifetime.

## Tips

!!! tip "Solver performance"
    For large fleets (100+ vehicles) over a full year, solving can take significant time. Start with a higher `MIPGap` (e.g. 0.05) for quick exploratory runs, then tighten for final results.

!!! tip "Custom infrastructure"
    Set `infrastructure_configurations: custom` in the run config and define all charger powers, costs, and battery limits directly in the same YAML file. This is useful for sensitivity analysis.

    Package 2 requires a valid Gurobi licence. Without it, the solver will fail. Academic licences are free at [gurobi.com](https://www.gurobi.com/academia/academic-program-and-licenses/).
